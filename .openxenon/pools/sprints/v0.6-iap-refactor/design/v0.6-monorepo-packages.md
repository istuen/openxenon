## 2. 依赖方向

```
packages/cli ──→ packages/engine ──→ (L2 → L1 → L0 内部单向)
      │
      ▼
  skills/ (静态资源)
```

- **cli 依赖 engine**：`import { create } from '@openxenon/engine/l2_iap_biz/Asset'`
- **engine 内部**：L2 → L1 → L0 单向
- **未来 apps/hall**：与 cli 平级，同样依赖 engine

## 3. 为什么 Daemon 放在 Engine 而非 CLI

| 理由 | 说明 |
|---|---|
| **状态连续性** | Daemon 需要持续 IAP 循环：监听文件变动 → 读写 L0 frozen.json → 调用 L2 Insight 算法。放在 Engine 内部避免跨 package 循环调用 |
| **常驻运行时** | Daemon = Engine 的后台运行实例。它不是"工具"，是引擎的持续模式 |
| **CLI 角色** | CLI 退化为纯控制器：`oxn daemon start` 只负责发送指令拉起 Engine 内部守护进程 |
| **Insight 计算归属** | Daemon 触发 Insight 计算，计算逻辑在 `l2_iap_biz/Insight/`——两者应在同一 package |

## 4. 为什么 Skills 放在 CLI 而非 Engine

| 理由 | 说明 |
|---|---|
| **静态注入** | Skills 是 AI 助手的指令手册，作为 CLI 的静态资源在 build 时嵌入。不参与 Engine 运行时 |
| **CLI 专属** | `oxn install-skill` 命令仅操作 Skills 文件，与 Engine 业务逻辑无耦合 |
| **Engine 独立** | Engine 对外 API 不包含 Skills 依赖——Hall / Web UI 不需要 Skills |

## 5. Bun Workspace 配置

```jsonc
// package.json (monorepo root)
{
  "workspaces": ["packages/*", "apps/*"],
  "scripts": {
    "build": "bun run --filter @openxenon/engine build && bun run --filter @openxenon/cli build",
    "typecheck": "bun run --filter '*' typecheck",
    "lint": "bun run --filter '*' lint"
  }
}
```

```jsonc
// packages/engine/package.json
{
  "name": "@openxenon/engine",
  "version": "0.6.0",
  "main": "src/index.ts",
  "exports": {
    "./l0_kernel/*": "./src/l0_kernel/*",
    "./l1_oxl_infra/*": "./src/l1_oxl_infra/*",
    "./l2_iap_biz/*": "./src/l2_iap_biz/*"
  }
}
```

```jsonc
// packages/cli/package.json
{
  "name": "@openxenon/cli",
  "version": "0.6.0",
  "main": "src/index.ts",
  "dependencies": {
    "@openxenon/engine": "workspace:*"
  }
}
```

## 6. CLI 调用 Engine 示例

```typescript
// packages/cli/src/commands/domain.ts
import { create, validate, list } from '@openxenon/engine/l2_iap_biz/Asset'
import type { CreateInput, ValidateInput } from '@openxenon/engine/l2_iap_biz/Asset/types'

const createSubcommand = defineCommand({
  async run(ctx) {
    const projectRoot = process.cwd()
    const result = await create({
      kind: 'domain',
      name: ctx.args.name as string,
      projectRoot,
    })
    output({ ok: true, data: result }, format)
  },
})
```

## 8. 迁移路径

| 阶段 | 内容 | 工期 |
|---|---|---|
| 1 | 新建 `packages/` 目录 + root `workspaces` 配置 | 1 day |
| 2 | 迁移 `src/kernel/` → `packages/engine/src/l0_kernel/` | 1 day |
| 3 | 迁移 `src/oxl/` + `src/infra/` → `packages/engine/src/l1_oxl_infra/`，拆分 oxl/infra 子目录 | 2 days |
| 4 | 拆分 `src/cli/` 业务逻辑 → `packages/engine/src/l2_iap_biz/`（六模块 DDD） | 1 week |
| 5 | 迁移薄 CLI → `packages/cli/src/commands/` | 2 days |
| 6 | 迁移 Skills → `packages/cli/skills/` | 1 day |
| 7 | CLI build 适配 bun compile + engine workspace 依赖 | 2 days |
| 8 | 全量测试 + ESLint 更新 + typecheck | 3 days |

**总工期**：~3 周
