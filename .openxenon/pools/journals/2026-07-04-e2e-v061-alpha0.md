## 3. 新发现的 Gap（写入 backlog）

### Gap #1：blueprint 未 chmod 0o444
**现象**：`oxn blueprint create` 落盘后 `644`，与 `oxn domain create` 行为不一致。
**根因推测**：`packages/cli/src/commands/blueprint.ts` 缺 `chmodSync(0o444)` 调用。
**优先级**：中（planLock 设计宣称的所有"创建即锁"对 blueprint 失效）。
**修复成本**：1 行代码 + 测试。
**建议归属**：v0.6.1 stable 收口前。

### Gap #2：work finalize 不强制收档条件
**现象**：`work finalize` 在 round verdict = FAILED 时仍能调用，status 收档为 `failed`。
**评估**：设计上是否正确？若"失败收档"是允许的（与 Skill §"v0.6 Round" 描述一致），则语义正确。
**建议**：Skill 文档明确"finalize 允许 FAILED 收档"。

### Gap #3：standalone proof 的 hash drift 验证路径未触发
**现象**：`proof show` 在篡改 frozen.json 后抛 schema-invalid，但未触发 hash drift 专项错误码。
**根因推测**：`proof verify` 仅在 `proofs-target-work` 注释（work-linked proof）下启用 hash 重算。
**评估**：可能符合设计 —— standalone proof 不需 content_hash 比对。但 changelog 描述的 v0.6.1-alpha.0 P1 修复**只在 work-linked 路径生效**。

### Gap #4：Intent/Align 模块缺失（继承自 Plan Mode G1）
**建议**：在 v0.6.3 W9 之前补建。

2. **`OXN_BLUEPRINT_DAG_CYCLE`**：未测试故意构造环路的 blueprint。
3. **`OXNI_INSIGHT_*`**（v0.6.2 才引入）：本次未测。
4. **Insight 强制人工审核 + OXN_AUTO_APPROVE**：v0.6.2 范畴。
5. **Daemon 进程实际启动**：v0.6.1 当前仅 CLI 占位，本 E2E 跳过。
6. **work migrate（V0→V1）**：本次未尝试造 V0 老布局测试。
