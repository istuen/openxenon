## 2. v0.3 目标（v3.1 锁定）

### 2.1 阶段 1 目标 — unified 接入 Kernel Schema

**核心问题**：如何把 Intent 5 类资产（.md 文件）解析为 OpenXenon Kernel Schema？

**端到端链路**：

```
[Intent MD file]
    │  1. unified pipeline 启动
    │     • remark-parse (CommonMark + GFM)
    │     • remark-directive (:::intent 容器指令)
    │     • remark-frontmatter (YAML)
    ▼
[mdast AST]
    │  2. 5 E_MD_xxx 校验
    │     • E_MD_INVALID_SYNTAX
    │     • E_MD_MISSING_REQUIRED
    │     • E_MD_TYPE_MISMATCH
    │     • E_MD_REFERENCE_BROKEN_FATAL
    │     • E_MD_HASH_MISMATCH
    ▼
[Validated mdast]
    │  3. mdast-to-kernel 转换器
    │     • domain → DomainSchema (Zod)
    │     • blueprint → BlueprintSchema (Zod)
    │     • work → WorkSchema (Zod)
    │     • task → TaskSchema (Zod)
    │     • proof → ProofSchema (Zod)
    ▼
[Kernel Schema (Zod 验证后)]
    │  4. IAP 引擎消费
    ▼
[Work execution + Proof verdict]
```

**关键交付**：

| 文件 | 行数估算 | 角色 |
|---|---|---|
| `src/oxl/md-bridge/pipeline.ts` | ~200 | unified pipeline 编排 |
| `src/oxl/md-bridge/remark-to-mdast.ts` | ~250 | .md → mdast AST |
| `src/oxl/md-bridge/mdast-validator.ts` | ~300 | 5 E_MD_xxx 校验 |
| `src/oxl/md-bridge/mdast-to-kernel.ts` | ~400 | 5 类 mdast → Kernel Schema |
| `src/oxl/md-bridge/cache.ts` | ~150 | contentHash 缓存 |
| `src/oxl/md-bridge/reference-checker.ts` | ~150 | 内部/外部引用分级 |
| `src/oxl/md-bridge/__tests__/*.test.ts` | ~600 | 30+ 单元测试 |
| `package.json` | +5 依赖 | unified / remark-parse / remark-directive / remark-frontmatter / mdast-util-from-markdown |

**L0–L3 兼容性**：

- L0-Schema：Zod 不感知上游（mdast vs Langium）— ✅

**2 周 ~3 周完成**。

### 2.2 阶段 2 目标 — Intent 5 类 .oxn ↔ .md 双轨制

**核心问题**：如何让 .oxn（v0.2.0 格式）与 .md（v0.3 格式）共存且不冲突？

**真值来源（A1 v3.1 §11.2 锁定）**：

> **`.md` = 唯一写入入口**。`.oxn` 由 `.md` 自动编译生成，**禁止反向修改**。

**双轨期数据流**：

```
用户/AI 编辑 .md
    ↓
pre-commit hook:
    1. 检测 .md contentHash
    2. 读取 .oxn sourceHash
    3. 若 H_md ≠ H_oxn：
       a. 触发 .md → .oxn 编译
       b. 更新 .oxn + sourceHash
       c. 写 meta: regenerated-from-md
    4. 若 H_md = H_oxn：跳过
    ↓
CI 守卫：
    • 拒绝 .oxn 手工修改（pre-commit hook）
    • 强制 .md 重新编译（hash mismatch）
    ↓
运行时：
    • Kernel 优先读 .oxn（v0.2.0 兼容）
    • v0.4+ 可切换优先读 .md
```

**关键交付**：

| 文件 | 行数估算 | 角色 |
|---|---|---|
| `src/oxl/oxl-md-adapter.ts` | ~300 | .oxn ↔ .md 双向 adapter |
| `src/oxl/oxl-md-compiler.ts` | ~200 | .md → .oxn 编译器 |
| `src/oxl/oxl-md-source-hash.ts` | ~100 | contentHash 管理 |
| `src/cli/<asset>-sync.ts` | ~150/类 | `oxn <asset> sync` 命令（5 类）|
| `src/cli/<asset>-md-create.ts` | ~150/类 | `oxn <asset> md-create`（5 类）|
| `.openxenon/.oxn-md-mapping.json` | — | .oxn ↔ .md 映射表 |
| 集成测试 | ~400 | 5 类 × 5 case = 25 case |

**双轨期 CI 守卫**：

```yaml
# .github/workflows/oxn-md-guard.yml
pre-commit:
  - .md 改动 → 自动触发 .oxn 重新编译
  - .oxn 改动 → 检测是否手工编辑，拒绝 commit
  - .oxn 改动未对应 .md 改动 → 拒绝 commit
```

**2 周完成**。

## 6. 风险与回退

| 风险 | 缓解 | 回退 |
|---|---|---|
| unified 生态与 L0-Processor 边界冲突 | mdast → Kernel Schema 经 Zod 验证层 | 保留 Langium 双轨 |
