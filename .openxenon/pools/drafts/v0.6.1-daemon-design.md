# v0.6.1 — 完整 Daemon 雏形 + Hall 骨架

> **Sprint 周期**：5 周（W1-W5）
> **前置依赖**：v0.6.0（已发布）
> **核心交付**：Daemon 进程 + 5 类可观测性 + Token 统计 + Insight 流入口 + Hall VitePress 静态站
> **架构层**：L1-Infra + L2-Engine + L3-CLI（Daemon 物理位置在 `src/daemon/`）

---

## 0. 目标与动机

v0.6.0 解决了"架构清晰"问题，但留下三个痛点：

1. **看不见**：Work 跑的过程没有任何持续可见的状态
2. **Token 黑盒**：无法知道 OXN Engine 自身消耗多少
3. **Insight 缺位**：AI 涌现的"发现/建议"无处可放

v0.6.1 一次性解决这三个痛点的前两个（第三个由 v0.6.2 解决），并交付**Hall 骨架**作为可视化界面。

### 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| Daemon 物理位置 | `src/daemon/` | 不迁入 engine，避免 L2-L3 循环依赖；与 v0.6 RFC 一致 |
| Hall 技术栈 | VitePress 静态站 | 复用 docs 站点依赖，**零新 npm 依赖** |
| Hall 路由 | `/hall/` 子路径 | docs 站点加子路由，不影响主站 |
| Token 统计精度 | 第一版按调用次数估算 | v0.7+ 引入 LLM SDK 真实计数 |
| 通知协议 | Webhook + stdout | Slack/Discord/终端三选一 |

## 2. 模块详细设计

### 2.1 Daemon 核心（`src/daemon/`）

**位置**：保持 v0.6 架构（`src/daemon/` 物理位置不迁入 engine）

**新增文件**：
- `src/daemon/supervisor.ts` — 进程监督（PID file + 自动重启）
- `src/daemon/file-watcher.ts` — 文件系统监听（frozen.json + state.json + events.jsonl）
- `src/daemon/webhook-notifier.ts` — Webhook 推送（Slack/Discord/终端）
- `src/daemon/insight-sink.ts` — Insight 信号入口（落 insight-raw 池）
- `src/daemon/commands/start.ts` — `oxn daemon start` 子命令
- `src/daemon/commands/stop.ts` — `oxn daemon stop` 子命令
- `src/daemon/commands/status.ts` — `oxn daemon status` 子命令
- `src/daemon/commands/health.ts` — `oxn daemon health` 子命令
- `src/daemon/__tests__/` — 单元测试

**接口**：
```typescript
// src/daemon/types.ts
export interface DaemonOptions {
  port: number                  // 预留 HTTP 端口（v0.7+ 用）
  webhookUrls: string[]         // Slack/Discord Webhook URLs
  watchPaths: string[]          // 监听 .openxenon/{works,proofs,pools}/
  healthRetentionDays: number   // health.json 保留天数（默认 7）
  enableInsightSink: boolean    // 是否自动落 insight-raw 池
}

export interface DaemonStatus {
  pid: number
  startedAt: string
  uptime: number
  eventsProcessed: number
  lastEventAt: string | null
  health: 'healthy' | 'degraded' | 'stopped'

```

### 2.2 Webhook 通知（`src/daemon/webhook-notifier.ts`）

**触发事件**（v0.6.1 覆盖 7 类）：

| 事件 | 触发时机 | Payload 关键字段 |
|---|---|---|
| `work.created` | `oxn work create` | workName, mode, assets |
| `work.locked` | `oxn work lock` | workName, planHash |
| `work.round.passed` | round verdict PASS | workName, round, duration |
| `work.round.failed` | round verdict FAIL | workName, round, failures |
| `work.finalized` | `oxn work finalize` | workName, totalRounds, finalVerdict |
| `proof.frozen.drift` | frozen.json SHA-256 不匹配 | proofName, expectedHash, actualHash |
| `insight.promoted` | `oxn insight promote` | insightId, targetAsset |

**Payload 格式**（通用）：
```json
{
  "event": "work.round.passed",
  "timestamp": "2026-07-15T10:23:45Z",
  "workName": "my-feature",
  "round": 2,
  "duration": 125000,
  "verdict": "PASSED"
}
```

**Webhook 发送**：HTTP POST + 重试 3 次（指数退避）+ 失败时写 `notify.log`

**终端输出**：stdout JSON Line（无 Webhook 配置时默认）

**OXNRC 配置**：
```json
{
  "daemon": {
    "webhookUrls": ["https://hooks.slack.com/services/..."],
    "notifyOn": ["work.round.failed", "proof.frozen.drift"]
  }
}
```

### 2.3 frozen.json 完整性 watch

**机制**：
- 启动时扫描所有 `proofs/*/frozen.json` 计算 SHA-256
- 写入 `.openxenon/daemon/frozen-snapshots.json`（带时间戳）
- 每 60 秒（可配）重新校验
- 文件被外部工具篡改 → 触发 `proof.frozen.drift` 事件

**防 OXN 自身误报**：OXN 写 frozen.json 时不触发 drift（通过 mtime 对比，30 秒内变更视为正常）

### 2.5 Hook 事件流

**写入格式**（`.openxenon/daemon/events.jsonl`）：
```json
{"timestamp":"2026-07-15T10:23:45.123Z","type":"hook.pre","hookName":"verify-asset-lock","workName":"my-feature","taskName":"implement-api","result":"allow","duration":12}
{"timestamp":"2026-07-15T10:23:46.456Z","type":"hook.post","hookName":"impact-analysis","workName":"my-feature","result":"warn","message":"modified 3 files outside blueprint scope","duration":145}
```

**Hook 类型**（v0.6.1 占位 + v0.6.4 完整化）：
- `hook.pre` — Work run/submit/finalize 前置
- `hook.post` — 后置
- `probe.run` — Probe 触发
- `lock.verify` — planLock 校验
- `drift.detect` — 文件 hash 漂移

### 2.6 Token 消耗统计

**写入格式**（`.openxenon/daemon/tokens.jsonl`）：
```json
{"timestamp":"2026-07-15T10:23:45Z","skillId":"oxn-work","category":"asset.inject","tokens":1820,"cacheHit":true}
{"timestamp":"2026-07-15T10:23:46Z","skillId":"oxn-work","category":"proof.run","tokens":3400,"cacheHit":false}
{"timestamp":"2026-07-15T10:23:47Z","skillId":"oxn-work","category":"insight.extract","tokens":850,"cacheHit":true}
```

**统计维度**（v0.6.1 第一版）：
- 按 skill 分类
- 按 category（asset / proof / insight / hook / cli）
- 按 cacheHit 标记

**精度说明**：v0.6.1 按调用次数 + 估算系数（不同类目不同 token 估算），**不读 LLM SDK 真实计数**——v0.7+ 引入真实计数。

### 2.7 Insight 流入口

**触发时机**：Work 状态变更为 `passed` / `failed` / `finalized`

**Insight 提取规则**（v0.6.1 最简版）：
- Work 失败时，从 trace.jsonl 提取最后 N 条 `asset_violations` 事件
- 写入 `.openxenon/pools/insight-raw/<workName>-<timestamp>.json`
- 包含：源头 trace 引用、workName、round、failure summary

**写入格式**：
```json
{
  "id": "insight-2026-07-15-my-feature-001",
  "createdAt": "2026-07-15T10:23:50Z",
  "workName": "my-feature",
  "round": 2,
  "type": "asset_violation",
  "summary": "3 files modified outside MemberContext domain scope",
  "evidence": {
    "traceRefs": ["trace.jsonl:142", "trace.jsonl:156"],
    "violationCount": 3
  },
  "status": "raw",
  "hash": "sha256:abc123..."
}
```

**v0.6.1 范围**：仅落 raw 池；**不**做跨 Work 聚合（v0.6.2 引入）、**不**做 promote（v0.6.2 引入 CLI）。

### 2.8 Hall VitePress 静态站（v0.6.1 骨架）

**位置**：`docs/.vitepress/hall/` （v0.6.5 完整化）

**v0.6.1 范围**：两个最基本面板
- `/hall/health/` — 渲染 `health.json` 摘要（work 数、失败模式、p95 耗时）
- `/hall/works/` — 列出所有 work（name / status / round / last update）

**v0.6.1 不做**：
- 实时刷新（用静态 + 手动刷新）
- 交互（纯展示）
- WebSocket 推送（v0.8 引入）

**技术细节**：
- VitePress 已支持自定义主题，从 `health.json` 读取（构建期或运行时 fetch）
- 优先运行时 fetch（保证实时）；构建期静态化（兜底）

**访问**：
```bash
bun run docs:dev
# → http://localhost:5173/hall/
```

## 6. 关键代码片段

### 6.1 supervisor.ts 核心

```typescript
import { writeFile, readFile, unlink } from 'node:fs/promises'
import { existsSync } from 'node:fs'
import { join } from 'node:path'

const PID_FILE = join('.openxenon', 'daemon', 'daemon.pid')

export async function startDaemon(options: DaemonOptions): Promise<DaemonStatus> {
  // 1. 检查 PID file
  if (await isDaemonRunning()) {
    throw new IAPError('IAP_DAEMON_ALREADY_RUNNING', { pid: await readPid() })
  }

  // 2. fork 子进程
  const child = fork(join(import.meta.dir, 'worker.js'), [], {
    detached: true,
    stdio: ['ignore', 'pipe', 'pipe', 'ipc']
  })

  // 3. 写 PID file
  await writeFile(PID_FILE, String(child.pid))

  // 4. 启动文件监听 + Webhook + Insight sink
  child.send({ type: 'init', options })

  return {
    pid: child.pid!,
    startedAt: new Date().toISOString(),
    uptime: 0,
    eventsProcessed: 0,
    lastEventAt: null,
    health: 'healthy'
  }
}

export async function stopDaemon(): Promise<void> {
  const pid = await readPid()
  if (!pid) return
  process.kill(pid, 'SIGTERM')
  // 等 5 秒，强杀
  setTimeout(() => {
    if (existsSync(`/proc/${pid}`)) {
      process.kill(pid, 'SIGKILL')
    }
  }, 5000)
  await unlink(PID_FILE).catch(() => {})
}

export async function isDaemonRunning(): Promise<boolean> {
  const pid = await readPid().catch(() => null)
  if (!pid) return false
  try {
    process.kill(pid, 0)  // 探测进程是否存在
    return true
  } catch {
    await unlink(PID_FILE).catch(() => {})
    return false
  }
}
```

### 6.2 webhook-notifier.ts Payload 构造

```typescript
type WebhookEvent =
  | 'work.created' | 'work.locked'
  | 'work.round.passed' | 'work.round.failed'
  | 'work.finalized'
  | 'proof.frozen.drift'
  | 'insight.promoted'

interface WebhookPayload {
  event: WebhookEvent
  timestamp: string
  [key: string]: unknown
}

export async function notify(event: WebhookEvent, data: Record<string, unknown>): Promise<void> {
  const cfg = await loadDaemonConfig()
  if (cfg.notifyOn && !cfg.notifyOn.includes(event)) return

  const payload: WebhookPayload = {
    event,
    timestamp: new Date().toISOString(),
    ...data
  }

  // 1. 终端输出（无 Webhook 时默认）
  if (!cfg.webhookUrls?.length) {
    console.log(JSON.stringify(payload))
    return
  }

  // 2. Webhook 推送（重试 3 次）
  for (const url of cfg.webhookUrls) {
    await retry(async () => {
      const res = await fetch(url, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payload)
      })
      if (!res.ok) throw new Error(`HTTP ${res.status}`)
    }, { retries: 3, backoff: 'exponential' })
  }
}
```

## 7. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Daemon 进程在 macOS 后台被系统杀死 | 中 | 中 | `launchd` 集成（v0.6.3 引入） |
| Webhook 推送失败导致漏报 | 低 | 低 | 重试 3 次 + 失败日志 |
| frozen.json 完整性 watch 误报 OXN 自身写入 | 中 | 中 | mtime 30 秒阈值 |
| Token 估算系数不准确 | 中 | 低 | v0.6.1 仅作粗粒度；v0.7+ 真实计数 |
| VitePress 编译失败阻塞 docs 站点 | 低 | 高 | Hall 失败不阻塞主站（独立 build） |
| Hall 实时 fetch 失败 | 中 | 低 | 构建期静态化（兜底） |
