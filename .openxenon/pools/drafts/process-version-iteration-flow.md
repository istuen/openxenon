## 0. 当前问题

v0.2.0 冻结时暴露的版本管理分裂：

| 元素 | 现状 | 问题 |
|---|---|---|
| 需求 | `.openxenon/requirements/`（不存在）| 不完整 |

| version:sync | 仅更新 README.md | 漏其他文件 |

## 1. 端到端流程

```
[需求层]
  PM 写 pools/design/req-<name>-v<X.Y.Z>.md
   ↓
  AI 评审 / 人类审阅 / 标记 ::status draft → approved
   ↓
[设计层]
  Architect 写 pools/design/{dev-design,test-design,product,arch}-<topic>-v<X.Y.Z>.md
   ↓ ::references [requirements, intent/]
  AI 解析 ::references 引用图
   ↓
[实施层]
  Dev 启动 Work: .openxenon/works/<name>/work.md
   ↓ ::aligns [design, intent/]
  AI 解析 ::aligns，自动 task 拆分
   ↓
  Task 实施: .openxenon/works/<name>/tasks/<task>.md
  Probe 验证 → 写 .openxenon/proofs/<proof-name>/verdict.md (frozen)
   ↓
[复盘层]
  QA 写 pools/audit/{audit,retro}-v<X.Y.Z>-<name>.md
  Architect 写 pools/journal/YYYY-MM-DD-<event>.md
   ↓
[发布层]
  oxn version:check (全 .openxenon 目录一致性)
  oxn version:aggregate (从所有 .openxenon/** 聚合)
  oxn version:release (bump + tag + archive)
   ↓
  design/changelog/v0.X.md (auto-generated)
  package.json bump
  git tag v0.X.0
```

**v0.3 增强**：

```ts
const files = [
  { path: 'README.md', pattern: /版本:\s*[\d.]+/ },
  { path: 'package.json', pattern: /"version":\s*"([\d.]+)"/ },
  // 当前 .openxenon/ 目录
  { path: '.openxenon/design/changelog/CHANGELOG.md', pattern: /##\s*\[([\d.]+)\]/ },
  // intent/ 资产
  ...(await glob('.openxenon/domains/*.md')).map(p => ({
    path: p, pattern: /^version:\s*([\d.]+)$/m
  })),
  ...(await glob('.openxenon/blueprints/*.md')).map(p => ({
    path: p, pattern: /^version:\s*([\d.]+)$/m
  })),
  // align/ work
  ...(await glob('.openxenon/works/*/work.md')).map(p => ({
    path: p, pattern: /work:\s*v0-(\d+)-/  // 提取 version
  })),
  // proof/ verdict
  ...(await glob('.openxenon/proofs/*/verdict.md')).map(p => ({
    path: p, pattern: /^work:\s*v0-(\d+)-/m
  })),
  // pools/
  ...(await glob('.openxenon/pools/**/*.md')).map(p => ({
    path: p, pattern: /^version:\s*([\d.]+)$/m
  })),
]
```

**职责**：
- 验证 `package.json` 与所有 `.openxenon/**` MD 资产的 version 一致
- 验证 deprecated 资产不参与一致性（但可读）
- 失败时给出精确错误（哪份文档与 package.json 不一致）

### 2.2 `scripts/version-aggregate.ts`（新）

**职责**：
- 扫描 `.openxenon/` 全目录（domains/blueprints/works/proofs/pools/）
- 按 version 聚合所有变更
- 生成 `design/changelog/v0.X.md`（auto-generated）
- 生成 `design/changelog/CHANGELOG.md`（入口索引）

**聚合策略**：

```ts
interface AggregateOptions {
  version: string;                    // e.g. "0.3.0"
  sinceVersion: string | null;        // e.g. "0.2.0" (null = 全量)
  outputPath: string;
  format: 'md' | 'json';              // md = 人类读, json = 机器读
}

async function aggregate(options: AggregateOptions) {
  // 1. 扫描 intent/ 新增/修改的 Domain 和 Blueprint
  const intentChanges = await scanIntent(sinceVersion, version);
  // 2. 扫描 pools/ 新增/修改的所有 v0.X/ 文档
  const designChanges = await scanPools(version);
  // 3. 扫描 align/ 已 submit 的 work
  const alignChanges = await scanAlign(version);
  // 4. 扫描 proof/ 已 frozen 的 verdict
  const proofChanges = await scanProof(version);
  // 5. 聚合 → 渲染 CHANGELOG.md
  return render({
    version,
    sections: [
      { title: 'Added (Domain)', items: intentChanges.domains },
      { title: 'Added (Blueprint)', items: intentChanges.blueprints },
      { title: 'Added (Pools)', items: designChanges },
      { title: 'Added (Work)', items: alignChanges },
      { title: 'Verified (Proof)', items: proofChanges },
      { title: 'Audited', items: await scanAudits(version) },
      { title: 'Journaled', items: await scanJournals(version) },
    ],
  });
}
```

### 2.3 `scripts/version-release.ts`（新）

**5 步原子化**：

```ts
async function release(version: string) {
  // 1. check
  await runCheck();  // version:check 必须绿
  // 2. aggregate
  await runAggregate(version);  // 生成 design/changelog/v0.X.md
  // 3. release notes draft
  const notes = await generateReleaseNotes(version);
  // 4. bump + tag
  await bumpPackageJson(version);
  await createGitTag(`v${version}`, notes);
  // 5. archive
  await archiveOldChanges();  // .changes/ 重组到 pools/audit/
}
```

## 4. 与现有 `.changes/` 的关系

### 4.1 阶段 1-3（v0.3 实施期）

- 保留 `.changes/`（不破坏现有 60 片段）
- `version:aggregate` 暂不读 `.changes/`
- 60 片段作为"历史快照"保留

### 4.2 阶段 5（物理删除期）

- `version:release` 调用 `archiveOldChanges()`
- 把 60 片段按 version 重组：
  - `0-0-X-*.md` → `pools/audit/v0.0.x/` (历史归档)
  - `0-1-X-*.md` → `pools/audit/v0.1.x/`
  - `0-2-0-*.md` → `pools/audit/v0.2.0/` 或 `pools/audit/retro-v0.2.0-sprint-N/`
- `.changes/` 目录删除

### 4.3 替代品

- 未来所有变更通过 `.openxenon/` 4 类资产（domains/blueprints/works/proofs/pools/）表达
- `version:aggregate` 从 `.openxenon/**` 自动聚合
- 单一 SSOT 取代分散片段
