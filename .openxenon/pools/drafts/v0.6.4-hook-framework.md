# v0.6.4 — Hook 框架深化（Pre/Post + OXL hook 语法）

> **Sprint 周期**：2 周（W1-W2）
> **前置依赖**：v0.6.1（Hook 事件流 events.jsonl 已就位）
> **核心交付**：Pre/Post Hook 钩子点 + OXL hook 语法 + disable-model-invocation + Hall 可视化
> **架构层**：L1-OXL（grammar）+ L2-Work（钩子点）+ L3-CLI（执行器）

---

## 0. 目标与动机

v0.6.0 的 Hook 机制只在 `Work` 完成后触发（proof.run / drift.detect），**没有在 AI 行动过程中插入干预点**。

参考 [Harness Engineering](https://mp.weixin.qq.com/s/nBtSvz9PruWe8R2UXUwQwA) 文章的 Hook 体系（**PreToolUse / PostToolUse / Stop**），v0.6.4 引入三时机钩子，把"硬阻断"从事后扩展到事中。

### 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 钩子时机 | Pre / Post / Stop（对齐 Claude Code Hook） | 行业标准，工程师熟悉 |
| 钩子定义位置 | OXL grammar 加 `hook` 语法 | Asset/Blueprint 可声明附加钩子 |
| 钩子类型 | shell / probe / deny / ask | 灵活但保持简单 |
| disable-model-invocation | Probe 标记后跳过 LLM 走脚本 | 节省 token（Harness 文章核心） |
| 失败策略 | 默认 deny，可配置 ask | 与 Hook 标准一致 |
| Hall 可视化 | v0.6.1 events.jsonl 已有 | 仅增强展示层 |

## 1. 核心概念：Hook 时机

```
┌─────────────────────────────────────────────────────────┐
│                      Work 生命周期                       │
│                                                          │
│  Pre-Hook  →  [AI Action]  →  Post-Hook  →  Stop-Hook  │
│   (行动前)         ↑              (行动后)        (停止时)│
│   校验边界       执行任务        影响面分析      最终检查  │
│   planLock       写文件          hash drift      frozen  │
│                                                          │
│  ↓ 失败可 deny（硬阻断） / ask（询问） / allow（通过）  │
└─────────────────────────────────────────────────────────┘
```

**三时机映射**：

| Hook 时机 | 触发场景 | 典型用途 |
|---|---|---|
| **Pre-Hook** | Work run / submit / finalize 前 | 校验 planLock / 资产完整性 / lint |
| **Post-Hook** | task.submit / probe.run 后 | 影响面分析 / hash drift 校验 / autoformat |
| **Stop-Hook** | Work finalize 前 | 类型检查 / 文档生成 / 最终 lint |

**对齐 Claude Code Hook**：
- Claude Code 用 PreToolUse / PostToolUse / Stop
- v0.6.4 用 Pre / Post / Stop（去掉 ToolUse 命名，因为 OXN 不是工具调用模型，而是状态机驱动）

## 2. OXL Grammar 扩展

### 2.1 Hook 声明

```langium
// src/oxl/langium/oxn.langium (增量)
HookDeclaration:
  ('pre-hook' | 'post-hook' | 'stop-hook') name=STRING '{'
    ('type' ':' type=HookType)?
    ('script' ':' script=STRING)?
    ('probe' ':' probe=ProbeRef)?
    ('scheme' ':' scheme=STRING)?
    ('on' ':' on=HookOn)?
    ('fail' ':' fail=FailStrategy)?
    ('disable-model-invocation' ':' disableModelInvocation=BOOL)?
  '}';

enum HookType:
  SHELL = 'shell'
  | PROBE = 'probe'
  | DENY = 'deny'
  | ASK = 'ask';

enum HookOn:
  WORK_RUN = 'work.run'
  | WORK_SUBMIT = 'work.submit'
  | WORK_FINALIZE = 'work.finalize'
  | TASK_SUBMIT = 'task.submit'
  | PROBE_RUN = 'probe.run'
  | ALL = 'all';

enum FailStrategy:
  DENY = 'deny'
  | ASK = 'ask'
  | WARN = 'warn';
```

### 2.2 Domain / Blueprint 加 hooks 段

```oxl
blueprint "dev-workflow" {
  scope: context
  
  hooks {
    pre-hook "verify-asset-lock" {
      type: shell
      script: "oxn work validate"
      on: work.run
      fail: deny
    }
    
    post-hook "impact-analysis" {
      type: probe
      scheme: "git-diff-stats"
      on: task.submit
      fail: warn
    }
    
    stop-hook "final-typecheck" {
      type: shell
      script: "bun run typecheck"
      on: work.finalize
      fail: deny
      disable-model-invocation: true   # 节省 token
    }
  }
  
  slot "build" { ... }
}
```

**Domain 也支持 hooks**（用于全局约束）：
```oxl
domain "SecurityContext" {
  scope: always
  
  hooks {
    pre-hook "secret-scan" {
      type: shell
      script: "git secrets --scan"
      on: all
      fail: deny
      disable-model-invocation: true
    }
  }
  
  invariant { ... }
}
```

## 3. 钩子执行器（`packages/engine/src/Work/hook-runner.ts`）

### 3.1 核心接口

```typescript
// packages/engine/src/Work/hook-runner.ts (L2)
export interface HookDefinition {
  name: string
  type: 'shell' | 'probe' | 'deny' | 'ask'
  script?: string              // shell
  probe?: ProbeRef             // probe
  on: HookOn
  fail: 'deny' | 'ask' | 'warn'
  disableModelInvocation?: boolean
}

export interface HookContext {
  workName: string
  taskName?: string
  phase: 'pre' | 'post' | 'stop'
  artifacts: string[]          // 受影响的文件路径
  metadata: Record<string, unknown>
}

export type HookResult =
  | { action: 'allow' }
  | { action: 'deny'; reason: string }
  | { action: 'ask'; prompt: string }
  | { action: 'warn'; message: string };

export async function runHooks(
  phase: 'pre' | 'post' | 'stop',
  hookDefs: HookDefinition[],
  ctx: HookContext
): Promise<HookResult> {
  // 1. 过滤出当前 phase 的 hook
  const applicable = filterApplicable(hookDefs, phase, ctx)
  
  // 2. 按顺序执行（fail 时按 fail strategy 决定）
  for (const hook of applicable) {
    let result: HookResult
    
    if (hook.disableModelInvocation || hook.type === 'shell' || hook.type === 'probe') {
      // 脚本/Probe：直接执行，不调 LLM
      result = await executeScript(hook, ctx)
    } else if (hook.type === 'deny') {
      // deny：直接拒绝
      result = { action: 'deny', reason: `Hook ${hook.name} denied` }
    } else {
      // ask：调 LLM 决策（v0.6.4 简化：直接 deny with prompt）
      result = { action: 'ask', prompt: `Hook ${hook.name} requires user confirmation` }
    }
    
    // 3. 记录到 events.jsonl
    await logHookEvent(phase, hook, ctx, result)
    
    // 4. 处理失败
    if (result.action === 'deny') {
      if (hook.fail === 'deny') return result
      if (hook.fail === 'warn') console.warn(result.reason)
      // ask 留给上层处理
    }
  }
  
  return { action: 'allow' }
}
```

### 3.3 disable-model-invocation 优化

**关键路径**（v0.6.4 引入）：
```
Hook 执行决策树：
  hook.type === 'shell'      → 直接 exec 脚本（不调 LLM）
  hook.type === 'probe'      → 直接调 probe runner（不调 LLM）
  hook.type === 'deny'       → 直接拒绝（不调 LLM）
  hook.type === 'ask'        → 调 LLM 决策（v0.6.4：仅记录，不阻塞）
  hook.disableModelInvocation === true → 同上，强制跳过 LLM
```

**Token 节省示例**：
- `secret-scan` hook（pre-hook, type=shell）：每次 Work run 节省 ~500 tokens（避免 LLM 判断）
- `final-typecheck` hook（stop-hook, type=shell, disableModelInvocation=true）：每次 finalize 节省 ~800 tokens

## 6. 关键代码片段

### 6.1 executeScript 路径

```typescript
async function executeScript(hook: HookDefinition, ctx: HookContext): Promise<HookResult> {
  if (hook.type === 'shell' && hook.script) {
    const { stdout, stderr, exitCode } = await runShell(hook.script, ctx)
    
    if (exitCode === 0) {
      return { action: 'allow' }
    }
    return {
      action: hook.fail === 'warn' ? 'warn' : 'deny',
      reason: `Shell hook failed: ${stderr || stdout}`
    }
  }
  
  if (hook.type === 'probe' && hook.probe) {
    const result = await runProbe(hook.probe, ctx)
    if (result.verdict === 'PASSED') {
      return { action: 'allow' }
    }
    return {
      action: hook.fail === 'warn' ? 'warn' : 'deny',
      reason: `Probe ${hook.probe} verdict: ${result.verdict}`
    }
  }
  
  return { action: 'allow' }
}

async function runShell(script: string, ctx: HookContext): Promise<ShellResult> {
  // 1. 替换 ${ctx.*} 变量
  const resolved = script
    .replace(/\$\{workName\}/g, ctx.workName)
    .replace(/\$\{taskName\}/g, ctx.taskName ?? '')
    .replace(/\$\{phase\}/g, ctx.phase)
  
  // 2. exec（同步，最多 30s）
  return await execAsync(resolved, { timeout: 30_000 })
}
```

### 6.2 logHookEvent

```typescript
async function logHookEvent(
  phase: 'pre' | 'post' | 'stop',
  hook: HookDefinition,
  ctx: HookContext,
  result: HookResult
): Promise<void> {
  const event = {
    timestamp: new Date().toISOString(),
    type: `hook.${phase}` as const,
    hookName: hook.name,
    hookType: hook.type,
    workName: ctx.workName,
    taskName: ctx.taskName,
    result: result.action,
    duration: 0,  // TODO: 测量
    ...(result.action === 'deny' ? { reason: result.reason } : {}),
    ...(result.action === 'warn' ? { message: result.message } : {})
  }
  
  await appendJsonl('.openxenon/daemon/events.jsonl', event)
}
```

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Hook 脚本执行超时 | 中 | 中 | 默认 30s timeout + abort |
| Hook 副作用污染 git | 中 | 中 | shell hook 默认只读；写操作需显式 allow |
| disableModelInvocation 误用 | 低 | 中 | 强制 type=shell/probe 才允许此字段 |
| Hook 数量过多拖慢 Work | 中 | 低 | 并行执行 + early-exit on first deny |
| 钩子失败导致 Work 卡住 | 低 | 高 | 详细错误信息 + 跳过 hook 选项（仅限 deny） |
| OXL grammar 兼容破坏 | 低 | 高 | 旧 .oxn 无 hooks 段仍可解析 |
