## v1.0.0 — 临界点 + CAS 完整化 + Engine 独立发布

**发布日期**：2027-08-15（预计）

### 关键变更

- **临界条件识别**：数据驱动识别"复杂度 × 失败率 × 历史"组合阈值

- **CAS 七要素**：多样性 / 流 / 标识 / 内部模型 / 积木块 / 聚集 / 非线性
- **Engine 独立发布**：`@openxenon/engine` 单独发包

## v1.1+ — 综合集成（钱学森"从定性到定量"）

**发布日期**：2027-11 起

> **明示约束**：v1.x 开始，文档可适度提及"涌现 / 临界点 / 自组织"等概念，但仍以工程语言为主。

### 关键变更

- **定性→定量转换**："代码风格偏好"等定性描述自动转化为可度量规则集
- **专家知识显式化**：通过对话提取工程师经验，自动生成 Asset 模板
- **人机共创空间**：工程师在 AI 执行过程中实时干预意图/规则
- **跨组织 Insight**（opt-in）：多团队 Insight 聚合

### 长期愿景

- OpenXenon 从"工具"演进为"基础设施"
- 支持跨组织、跨项目的人机协作
- 工程师通过 OXN 形成"工程智慧沉淀平台"

## 关键约束（每阶段必守）

| 约束 | 含义 | 检验方式 |
|---|---|---|
| **三轴主导权不交叉** | 工程师 / AI / OXN 各司其职 | ESLint |
| **Proof 不可绕过** | Daemon 硬阻断 + 无 `--force` | 单元测试 |
| **AI 不直接反写 Asset** | Insight 反哺必须人工 `apply` | code review |
| **轻量级工程边界** | 不破坏 v0.6 收敛的 E1-E4 | architecture-guard |
| **强制人工审核** | 永不自动 apply/promote | 错误码 + 警告 |
| **对外不引系统科学** | 工程师视角 | 文档 review |
| **工程师主权不动** | 工具定位 | 架构不变性测试 |

---

## 不在任何阶段范围（明确不做）

| 功能 | 理由 |
|---|---|
| OpenXenon 自我意识 | 工具定位 |
| AI 自主反写 Asset | 工程师主权 |
| 取代工程师做决策 | 工具定位 |
| 大模型训练数据收集（默认） | 隐私 |
| 跨组织 Insight 共享（默认） | 隐私 + opt-in |
| 实时多人协作（多工程师同时编辑） | 复杂度过高，v2.0+ 考虑 |
