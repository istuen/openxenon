## 0. 背景与动机

### 0.1 当前问题

OXN v0.6.1-alpha.0 三个结构性空白：

1. **新项目引导空白**：`oxn init` 后到第一个 Asset 创建之间无 AI 引导。AI 不知道"项目需要哪些 Domain/Blueprint"。
2. **Pool 5 种分裂**：`research/design/issue/audit/journal` 五种语义边界模糊，工程师难以选择；5 目录维护成本。
3. **Insight 单源**：`pipeline-compute` 仅消费 `frozen.json + domains + blueprints + works + proofs`，**不消费外部知识**（项目文档 / 依赖更新 / Issue / 工程师讨论）。

### 0.2 闭环断裂示意

```
[现状 v0.6.1-alpha.0]

oxn init
   ↓ 空白（无 Asset 推荐）
Asset create (手动)
   ↓
Work → Proof → frozen.json
   ↓
Insight (单源: frozen + domains + blueprints)
   ↓
audit pool (5 种分裂)
   ↓ 人工 apply
Asset 修改
   ↓ 闭环断（无 Memory 累积）
[外部知识 / 工程师讨论 / Insight pattern 无法沉淀]
```

### 0.3 闭环愿景

```
[v0.7.x 愿景]

                   External Knowledge
                   (docs / issues / deps / discussions)
                          ↓ 工程师手动 ingest / Insight 自动 collect
                   ┌─────────────────────┐
                   │   Memory (聚合层)    │
                   │   .openxenon/memory/ │
                   └──────────┬──────────┘
                              ↓ 双向
                   ┌─────────────────────┐
                   │   Insight (双源)    │
                   │   内部 + Memory     │
                   └──────────┬──────────┘
                              ↓ 推荐
                   ┌─────────────────────┐
                   │   Asset + Work      │
                   └──────────┬──────────┘
                              ↓ 累积
                   ┌─────────────────────┐
                   │   Memory (闭环)     │
                   └─────────────────────┘
```

### 1.2 MemoryEntry Schema（核心数据结构）

```typescript
// packages/engine/src/kernel/schemas/memory-entry-schema.ts

export const MemorySourceSchema = z.enum(['external', 'engineer', 'agent'])

export const MemoryTypeSchema = z.enum([
  'research',          // 调研笔记（Pool research 兼容）
  'design',            // 设计文档（Pool design 兼容）
  'issue',             // 问题分析（Pool issue 兼容）
  'audit',             // 改进建议（Pool audit 兼容 — Insight apply 主用）
  'journal',           // 时间线（Pool journal 兼容）
  'dependency_update', // 依赖版本更新（harness-3.md MemoryEntry.type 候选）
  'doc_note',          // 项目文档注释
  'discussion',        // 工程师讨论记录
  'test_result',       // 测试结果（harness-3.md MemoryEntry.type 候选）
])

export const MemoryEntrySchema = z.object({
  // 标识
  id: z.string().regex(/^mem-\d{4}-\d{2}-\d{2}-\d{3}$/),

  // 来源 + 类型
  source: MemorySourceSchema,
  type: MemoryTypeSchema,

  // 内容
  title: z.string().min(1),
  content: z.string(),                    // markdown body

  // 信任度
  trustScore: z.number().min(0).max(1),    // 详见 ADR-0045
  ttl: z.number().int().nullable(),        // 秒；null = 永不过期

  // 关联
  relatedAssetIds: z.array(z.string()).default([]),
  relatedRoadmapItem: z.string().nullable().default(null),

  // 时间
  timestamp: z.number().int(),             // ms epoch

  // v0.5 Pool 兼容
  approval: ApprovalRecordSchema.nullable().default(null),
  supersededBy: z.string().nullable().default(null),

  // 元
  tags: z.array(z.string()).default([]),
})
```

## 2. MemoryEntry 来源与 trust_score 分级（Q4=B）

### 2.1 trust_score 分级

| trust_score | 来源 | 写入方式 | 用途 |
|---|---|---|---|
| **1.0** | `engineer` | 工程师手动 `oxn memory ingest` | 最高权威 |
| **0.7-0.9** | `engineer` + reference | 工程师确认的 Insight 推荐 | 高权威 |
| **0.5-0.7** | `agent` | Insight 自动产出 | 中等（需后续确认） |
| **0.3-0.5** | `external` | 外部抓取（webhook / 手动 paste） | 低权威，TTL=30d |
| **0.0-0.3** | 任意 | 低质信息 | 立即进入 `archive/` |

### 2.2 trust_score 自衰减

详见 [ADR-0045](../../../../forges/sprints/archive/docs-tmp-era/decisions/0045-ttl-decay-formula.md)：

```
t_current = max(0, T0 - (now - timestamp) / ttl * (T0 - 0.3))
```

例：
- trust=1.0, ttl=30d, elapsed=15d → 1.0 - 15/30 * 0.7 = **0.65**
- trust=0.7, ttl=30d, elapsed=30d → 0.7 - 1.0 * 0.4 = **0.30**（边界）

### 2.3 归档判定

```
shouldArchive(entry, now):
  if entry.supersededBy !== null: return true
  if entry.ttl !== null and now - entry.timestamp > entry.ttl * 1000: return true
  if decayTrustScore(entry, now) < 0.3: return true
  return false
```

`oxn memory gc` 触发实际归档到 `memory/archive/`。

### 5.2 memory-overwriter.ts（基于 intent-overwriter 复用）

```typescript
// packages/engine/src/Memory/memory-overwriter.ts
export interface OverwriteInput {
  memoryId: string                 // MemoryEntry.id
  targetPath: string               // Asset 物理路径
  meta: MemoryEntry                 // patch 在 content 字段
  operator?: string
  dryRun?: boolean
}

export interface OverwriteResult {
  path: string
  beforeHash: string
  afterHash: string
  approvalRecord: ApprovalRecord
  isDryRun: boolean
}

// 流程（与 intent-overwriter.ts 同构，但增加 chmod 0o444 恢复）
export function overwriteMemory(input: OverwriteInput): OverwriteResult {
  // 1. 目标文件存在性
  assertTargetExists(input.targetPath)

  // 2. 读当前 + 算 beforeHash
  const originalContent = readFileSync(input.targetPath, 'utf-8')
  const beforeHash = sha256(originalContent)

  // 3. 计算 newContent = applyPatch(original, meta.content)
  const newContent = applyPatch(originalContent, input.meta.content)
  const afterHash = sha256(newContent)

  // 4. atomic .draft.tmp → rename (v0.5 缺失，v0.7.x 实装)
  const draftPath = `${input.targetPath}.draft.tmp`
  const backupPath = `${input.targetPath}.bak`
  try {
    if (wasReadOnly(input.targetPath)) {
      chmodSync(input.targetPath, 0o644)
    }
    copyFileSync(input.targetPath, backupPath)  // .bak 备份
    writeFileSync(draftPath, newContent, 'utf-8')
    renameSync(draftPath, input.targetPath)    // atomic rename
    chmodSync(input.targetPath, 0o444)         // 恢复三层锁
  } catch (e) {
    // 回滚：从 .bak 恢复
    if (existsSync(backupPath)) {
      copyFileSync(backupPath, input.targetPath)
      chmodSync(input.targetPath, 0o444)
    }
    throw e
  } finally {
    if (existsSync(draftPath)) unlinkSync(draftPath)
  }

  // 5. 触发 validate 重算 planLock (v0.7.x 新增)
  // 注：此处调 spawn 子进程跑 `oxn domain validate <name>`
  // 详细实现见 ADR-0044

  return { path, beforeHash, afterHash, approvalRecord, isDryRun: false }
}
```

### 5.3 与 v0.5 intent-overwriter 的差异

| 维度 | v0.5 intent-overwriter | v0.7.x memory-overwriter |
|---|---|---|
| 写盘 | `writeFileSync` 直接覆盖 | `renameSync` 原子 + `.bak` 备份 + 回滚 |
| chmod | 维持可写（**0o644 漏**） | **0o444 恢复** |
| PlanLock 重算 | ❌ 缺失 | ✅ spawn `oxn validate` |
| 错误处理 | 无 try/finally | 完整 try/finally + 回滚 |
| 冲突检测 | `conflictsDetected: []` 永空 | 检测目标文件 hash 变化 |

```bash
oxn memory migrate-from-pools      # 从 v0.5 池迁移
```

### 8.2 查询



## 10. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Memory 取代 Pool 破坏 v0.6.1 已有 audit pool entry | 低 | 中 | 3 minor 兼容期 + migration 脚本 + .gitkeep |
| Onboarding wizard 推荐 Asset 不合理 | 中 | 中 | trust_score 0.5-0.7 + 工程师确认步骤 |
| Memory 注入 AI 上下文导致 Token 爆炸 | 中 | 高 | trust_score 阈值 + TTL 衰减 + 30 天归档 |
| MemoryEntry 数量爆炸 | 中 | 中 | M-6 TTL 自动归档 + `oxn memory gc` |
| `oxn memory apply` atomic rename 失败导致 Asset 半损坏 | 低 | 高 | .bak 备份 + try/finally + chmod 0o444 恢复 |
| Pool → Memory 迁移数据丢失 | 低 | 高 | dry-run 预览 + backup 目录保留 + 验证 hash |
| Insight 自动写入 Memory 与 Pool 并存期冲突 | 中 | 中 | Q2=B 一次性迁移 + 双写期 ≤ 1 minor |
| Roadmap 与 Memory 双向引用循环 | 低 | 低 | 单向：Roadmap 引用 Memory.id |

```bash
# → atomic rename + .bak 回滚 + chmod 0o444 恢复 + planLock 重算

$ oxn memory aggregate --cross-pool --since 7d
```
