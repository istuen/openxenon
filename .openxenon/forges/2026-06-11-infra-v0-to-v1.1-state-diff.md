## 2. v1.0 → v1.1 状态机差异对照表

### 2.1 实体布局

| 维度 | v1.0（脱节代码假设） | v1.1（当前实际） |
|---|---|---|
| 顶层实体 | Task | **Work**（Work 包含 N 个 Task） |
| 顶层配置 | `task.oxn`（单文件） | `work.oxn` + `tasks/<t>/task.oxn`（双层） |
| 路径模板 | `.openxenon/tasks/<taskId>/` | `.openxenon/works/<workId>/tasks/<taskId>/` |
| 单文件运行态 | `.openxenon/tasks/<id>/.task` | `.openxenon/works/<w>/.work`（单 JSON 文件，**不是**目录） |
| 沙箱路径 | `tasks/<id>/sandbox/` | `works/<w>/tasks/<id>/sandbox/` |
| Domain 注入 | task 级 | **work 级**（每个 task 继承 work 的 domains，`WORK_DOMAINS_JSON` 已存在） |
| 锁机制 | 无 | `.work.planLock`（work 级边界守卫） |
| 资产引用 | `arsenals/<type>/<name>/` | `arsenals/` + `builtin/` + `works/<w>/` **三层** |

### 2.2 状态机对比

| 阶段 | v1.0 | v1.1 | 影响 |
|---|---|---|---|
| Init | `oxn task init` | `oxn work init` | 顶层 entity 升级 |
| Migrate | 无 | `oxn work migrate`（v0→v1 数据迁移） | 需要 migrator（`src/work/work-migrator.ts` 已存在） |
| Create | `oxn task create` | `oxn work create` | 创建 work 含 work.oxn |
| Add-Task | 无 | `oxn work add-task` | work 内追加 task 子实体 |
| Validate | 隐含 | `oxn work validate` | work 级验证 |
| Lock | 无 | `oxn work lock`（`.work.planLock` 守卫） | sandbox 不应破坏 planLock |
| Run | `oxn task run` | `oxn work run` | 顶层命令 |
| Submit/Status | task 级 | work + task 双级 | 状态查询分级 |

### 2.3 Sandbox 路径差异

**v1.0（脱节代码）**：
```
projectRoot/.openxenon/tasks/<taskId>/sandbox/<basename(blueprint)>
```

**v1.1（应有）**：
```
projectRoot/.openxenon/works/<workId>/tasks/<taskId>/sandbox/<basename(task.oxn)>
```

→ 两份 `sandbox-manager.ts` 都在用 v1.0 布局，**均需修复**。

## 3. sandbox-manager 两份代码对比

| 维度 | `src/infra/sandbox-manager.ts` (L1-Infra) | `src/work/sandbox/sandbox-manager.ts` (L2-Work) |
|---|---|---|
| 调用方 | **无**（孤儿） | L2-Work 业务（待串联） |
| FS 抽象 | `import 'fs'` 直接调用 | `FileSystemPort` 注入（`fs?: FileSystemPort`） |
| DAG 校验 | `require('../oxn-dsl/validators/blueprint-dag')` | `import { validateDagTopology }` |
| yaml 解析 | `require('yaml')` | `require('yaml')`（同样不优雅） |
| 路径 | v1.0 错误 | v1.0 错误 |
| IR 形态 | `stages` + `concreteParts` 双套 | 同 L1 |
| 端口化 | ❌ | ✅（架构更优） |

**决策**：保留 L2-Work 版本（端口化 + 业务可变性更强）；删除 L1-Infra 孤儿。

## 5. StandardAsset 与 v1.1 资产解析重叠

### 5.1 现状重叠

| 体系 | 位置 | 范围 |
|---|---|---|
| `StandardAsset` | `src/infra/loader.ts:28-34` | 旧 Arsenal（`probes` / `blueprints` / `parts`） |
| `BuiltinAssetEntry` | `src/oxn-dsl/scope/oxn-scope.ts` | 内置资产（`@oxn/...`） |
| `ResolvedOxnAsset` | `src/oxn-dsl/scope/oxn-scope.ts` | 解析后资产（含 scope/resolvedFrom） |
| `OxnWorkspaceManager` | `src/oxn-dsl/scope/oxn-workspace-manager.ts` | `@oxn/ @prj/ @glo/` 命名空间解析器 |
| `OxnBuiltinRegistry` | `src/oxn-dsl/scope/oxn-builtin-registry.ts` | `@oxn/` 运行时注册表 |

### 5.2 调用现状

`StandardAsset` 仍有 3 处 type-only 消费方：
- `src/oxn-dsl/scope/oxn-scope.ts:215`
- `src/oxn-dsl/langium/oxn-document-builder.ts:5`
- `src/oxn-dsl/loader/oxn-loader.ts`（间接）

**结论**：`StandardAsset` 处于"半废弃"状态——`OxnWorkspaceManager` 才是 v1.1 资产解析的真实入口。

### 5.3 决策

本轮**不处理** `StandardAsset`，仅记录趋势。后续 v1.1 资产体系单点专项时统一处理。

## 6. 风险与开放问题

| 编号 | 风险 | 缓解 |
|---|---|---|
| R-1 | `TaskSandbox` 业务串联后无调用方（Phase 2 迁移后仍孤儿） | Phase 2 同时串联一个最小调用方（`oxn work add-task --sandbox`） |
| R-2 | `SandboxConfig.workId` 破坏 v1.0 兼容性 | 保留 workId 必填，旧调用方显式传 `workId: ''` 走 v1.0 路径 |
| R-3 | IR 合成（work.oxn + task.oxn）超出本轮范围 | 仅做路径修复，IR 合成留到"Work.Task 状态机重构"专项 |
| R-4 | DAG 校验 `validateDagTopology` 在 L1-OXN-DSL | 理想上移 L0-Kernel（`kernel/processors/dag.ts` 已有 `topologicalSortGeneric`），但本轮不动 |
| R-5 | 路径常量无真相源 | 仅记 TODO，v1.1 path 单点专项处理 |
