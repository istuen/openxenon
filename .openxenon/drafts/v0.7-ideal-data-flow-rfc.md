# v0.7 理想态数据流 RFC — Blueprint → Work → Task runtime 接通

> **RFC 状态**：📝 Draft（待 review）
> **目标版本**：v0.7.3
> **前置依赖**：v0.7.0（Domain 三层架构）+ ADR-0055（Blueprint 组合模板）+ ADR-0060（Domain 词汇边界）
> **核心交付**：Blueprint `## Use` / `## Boundaries` 接通 Work/Task runtime；多 Domain 同名 term 多视角注入；Workflow slot DAG 与 Task.deps DAG 联动；Stack.tools 注入 Probe runtime
> **来源**：调研 session（2026-07-17）：Task.context 实际为 skill_context；Blueprint IR 当前不进 runtime；4 个数据流断裂点

> **注意**：此文件由 plan mode 写入（受限于权限规则），最终归属应为 `.openxenon/pools/drafts/v0.7-ideal-data-flow-rfc.md`。退出 plan mode 后请用 `mv` 迁移，或直接编辑目标位置。

## 0. 背景与动机

v0.6.1 ADR-0055 已规定 Work `## Refs` 只接受 `kind: blueprint`，Domain/Workflow/Stack 通过 Blueprint 间接引用。v0.7.0 ADR-0060 D4 又规定同名特性词（如 OXL）可在 root + 多个子 Domain 多视角共存。

但 runtime 实现层未跟上：

1. `work-context-builder.ts:217-223` 仍按旧 `task.domain` 单值直接读 Domain，Work `## Refs` 中声明的多个 Domain 只取其 externals 元数据，**language{terms,bans,invariants} 全部丢弃**
2. `task.ts:34` `domain: string | null` 是单值字段，Task 只能绑 1 个 Domain 视角
3. `blueprints.json`（含 Blueprint + 3 边界 composite hash，已被 PlanLock hash）**完全不被 work-context-builder 读取**，仅用作 drift 检测
4. Blueprint `## Boundaries[].observe` 与 Task `## Probes` 无 lock 期联动，Workflow `## Slots` DAG 与 Task `## deps` DAG 互不校验

后果：ADR-0055 §D2 + ADR-0060 §D4 的"多视角组合"是**纸面规范**，AI 执行 Work 时实际只看到单 Domain 视角的 term desc，Blueprint 编排信息完全丢失。

本 RFC 是 v0.7 Domain 三层架构的 runtime 闭环。

## 1. 现状 4 个断裂点

| ID | 断裂 | 当前实现位置 | 应触发位置 |
|---|---|---|---|
| F1 | Blueprint `## Use` / `## Boundaries` 不进 runtime | `work-context-builder.ts` 不读 `blueprints.json` | Work lock 期 + Task run 期 |
| F2 | Work `## Refs` 只读 Domain externals，丢弃 language | `work-context-builder.ts:217-223` | 应改为读 Blueprint 引用 |
| F3 | Task.domain 单值字段，break-first 仅注入 1 个 Domain | `task.ts:34` + `work.ts:2225-2229` | 改为多 Domain 主/背景视角 |
| F4 | Blueprint observe / Workflow slots 不参与 runtime | 全无连接 | Task.probes ⊆ Boundary.observe；Task.deps ⊆ Workflow slot DAG |

证据：

- `work.ts:2225` `readDomainFile(path)` + `break` 只读 1 个候选 Domain
- `summary-extractors.ts:55 readDomainFile` 走 regex 路径，丢失 `## Terms: <分组>` 后缀和 multiline `- desc: |`（root oxn-domain.md 整段 Terms 段被 regex 跳过）
- `BlueprintIR.use/boundaries`（blueprint.ts:48-56）当前不被任何 runtime 消费
- Workflow `## Slots` 仅是 IR 元数据，无 runtime 校验路径

## 2. 理想态数据流

### 2.1 数据流全景图

```
┌──────────────────────────────────────────────────────────────────────┐
│  L1: Asset 层（静态 E1，已冻结）                                       │
├──────────────────────────────────────────────────────────────────────┤
│  Domain    .md   terms / bans / invariants / externals              │
│  Workflow  .md   slots (name + desc + deps + observe)               │
│  Stack     .md   tools (name + version + command + config + desc)   │
│  Blueprint .md   ## Use (三轴 Domain/Workflow/Stack URI 引用) +      │
│                  ## Boundaries (slot 级 refs/observe/deps)           │
└──────────────────────────────────────────────────────────────────────┘
                                ↓
                BlueprintIR（已由 extractBlueprintIR 实现）
                                ↓
┌──────────────────────────────────────────────────────────────────────┐
│  L2: Work 实例化（lock 期生成）                                         │
├──────────────────────────────────────────────────────────────────────┤
│  per-work blueprints.json（已被 planLock.blueprintsHash hash）       │
│   = BlueprintUse{domain[], workflow[], stack[]}                      │
│   + BlueprintBoundary[]（带 refs/observe/deps）                      │
│   + 每个 Domain/Workflow/Stack 文件 hash                              │
└──────────────────────────────────────────────────────────────────────┘
                                ↓
┌──────────────────────────────────────────────────────────────────────┐
│  L3: Task runtime（oxn work context --task X）                        │
├──────────────────────────────────────────────────────────────────────┤
│  WorkContextResult（扩展后）：                                          │
│   - context: work.context.goal + constraints + maxIterations         │
│   - blueprint: BlueprintIR（🆕 新增，从 blueprints.json 读）          │
│   - primaryDomain: task.domain（单值，主对齐视角）                     │
│   - backgroundDomains: Blueprint.use.domain[] - primaryDomain         │
│       （🆕 多视角 desc，标注 Domain 名）                                │
│   - workflowSlots: WorkflowIR.slots（🆕 Task.deps 锚点）              │
│   - stackTools: StackIR.tools（🆕 Probe runtime 注入）                │
│   - task: task.parts[].skill_context + task.##Probes                  │
│   - allowedLanguage: 主+背景 Domain 的 union{                         │
│       terms: [{ name, desc, domain: <Domain 名> }],                  │
│       banned: [...],                                                  │
│       invariants: [...]                                               │
│     }                                                                 │
│   - lockHealth + diagnostics                                          │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 多视角 desc 注入格式（D2 决策）

AI 上下文中 `## Allowed Language` 段重写为按 term 名聚合 + 标注视角来源：

```
## Allowed Language

### Terms (must use)

#### OXL
- [root] OpenXenon 的特定领域语言（DSL），用于声明与校验 OXN 实体
- [engine] Engine 通过 unified 库实现 MD 语法的特性，包括编译、校验

#### Kernel
- [engine] L0 纯逻辑验证模块；通过 Infra 调用带副作用的 Probe...
- [proof] L0 纯逻辑验证模块（公证人非裁判 ADR-0031）：零 IO 约束...

#### Work
- [root] 人机协作的工作空间...
- [work] Work 是 E2 人机协作的工作空间；编排流程 3 IAP 阶段...

### Banned
- [engine] 禁用旧术语 L2Domain/Tier/Stratum/...
- [cli] 禁用 Flag/Option/Switch...

### Invariants
- [engine] inv-3: Kernel 与 Infra 司法/行政分离...
- [work] inv-1: 3 IAP 阶段顺序不可跳...
```

`[Domain 名]` 标注让 AI 知道每个 desc 的视角来源，避免把不同视角的 desc 当成同一断言的多重确认。

### 2.3 Stack.tools 注入 Probe runtime（D5 决策）

当前 `task.md ## Probes ### X - params: - command: bun run typecheck` 是工程师手写 bun 路径。理想态下：

```ts
// ProbeRunner 接收 merged params:
//   params (task.md 内联) ← 优先
//   +
//   stackTool.params (Stack.tools[bun].config 自动派生: {
//     runtime: 'bun',
//     version: '1.3+',
//     lockfile: 'bun.lock',
//     timeout: 30000
//   })
```

Stack 注入不覆盖 task.md 显式 `params`，仅作为隐式环境约束（如 timeout 上限、版本下限）。

## 3. 决策点（D1-D7）

> 本 RFC 全部 D1-D7 采用推荐方向 a；如有 reviewer 反对请评论。

### D1 — Task.domain 演进策略：保留主/背景双视角【采纳 a】

`task.md ## Refs - domain: X` 保持单值字段（不动 TaskIR schema，避免破坏性变更），但语义升级为"**主对齐视角**"；`Blueprint.use.domain[]` 自动派生其余 Domain 为"**背景视角**"。

理由：
- a 保留 TaskIR schema 兼容性（不动 task.ts:31-38）
- a 让工程师在 Task 设计期显式选 1 个主对齐视角，避免"多 Domain 同名 term 谁说了算"的歧义
- a 背景视角仅作 desc 补充，不参与 lock 期校验的"主视角"语义

### D2 — 多 Domain 同名 term 注入格式：块状 + 视角标注【采纳 a】

每个同 name term 在 `## Allowed Language ### Terms` 下聚合为一个 H4 子节，下方按 Domain 视角列多行。

理由：
- a 让 AI 看到的多视角 desc 是结构化分块（不是 concat），避免 AI 把不同视角混为一个断言
- a `[Domain 名]` 标注与 ADR-0060 §D8 视角隔离原则一致

### D3 — Blueprint.boundaries[].observe 与 Task.probes 关系：lock 期 hard-check【采纳 a】

`task.md ## Probes ### X - ref: @oxn/probes/Y` 中的 Y 必须 ∈ Task 所对齐 slot 的 `Blueprint.boundaries[].observe[]`。lock 期 `oxn work lock` 校验失败 → IAP_INTENT_PROBE_OUT_OF_BOUNDARY (YIELD_TO_HUMAN)。

理由：
- a 让 Blueprint 真正成为 Probe 标准的 SSOT（替代 Work-domain.inv-25 / proof-domain.inv-22 的纯文本 invariant 约束）
- a 让 Blueprint 编排运行时生效，回归 ADR-0054 三边界框架设计意图

### D4 — Workflow.slot DAG 与 Task.deps DAG 关系：闭包校验【采纳 a】

Workflow `## Slots` 形成 slot DAG（slot.deps）；Task `## Tasks` 内每个 task.deps 必须对应 Workflow slot DAG 中**存在**的依赖边。lock 期校验：Task DAG ⊆ Workflow slot DAG 拓扑闭包。

理由：
- a 让 Workflow 重新成为"执行模板"（ADR-0054 设计意图），不只是文档元数据
- a 不阻断 Work 内部 task 编排自由（task 可比 slot 多但 DAG 必须可被 slot DAG 表达）

### D5 — Stack.tools 注入 Probe 上下文时机：runtime 注入 ProbeRunner【采纳 a】

`work-context-builder` 把 `Blueprint.use.stack` 解析得到的 `StackIR.tools` 传给 ProbeRunner；ProbeRunner 在执行 `@oxn/probes/shell-exec` 等需要环境的 Probe 时，把 tool 的 `version/command/config` 与 task 内 `params` 合并。

理由：
- a 工程师不再在 `task.md` 手写 `bun run typecheck`，只写 `command: run typecheck`，runtime 自动注入 `bun` 前缀 + 锁文件路径 + 超时上限
- a Stack 资产回归"实现层约束"语义（ADR-0054）

### D6 — Work `## Refs` 兼容性：旧 `kind: domain` deprecation warn【采纳推荐】

ADR-0055 已规定 Work `## Refs` 只接受 `kind: blueprint`，但 `trust-closure/work.md` 等历史 Work 仍有 `kind: domain`。

方案：
- v0.7.3 lock 期：检测到 `kind: domain` 触发 `OXN_WORK_LEGACY_DOMAIN_REF` 软警告（不阻断 lock，记录到 diagnostics）
- v0.8.0 lock 期：硬阻断（IAP_INTENT_LEGACY_DOMAIN_REF_BLOCKED）

理由：
- 给历史 Work 一个 migrate 窗口
- 不立即 hard cut 防止 v0.7.3 release 阻碍

### D7 — PlanLock hash 公式扩展：不动公式，只让 work-context-builder 读 blueprints.json【采纳推荐 a】

`plan-hash.ts:159 hashWorkPlan` 当前算 4 个 hash（workMd / blueprints / tasks / all），其中 `blueprintsHash` 已是 composite（含 Blueprint + 3 边界）。无需新加 hash 字段。

只需让 `work-context-builder.ts` 把 `works/<w>/blueprints.json` 真正读出来（当前根本不读），从中反序列化 `BlueprintUse` + `BlueprintBoundary[]` + 边界文件路径列表，加载各边界文件 IR。

理由：
- a 不动 PlanLock schema 避免破坏向后兼容
- a blueprints.json 已是 SSOT 的 Blueprint 编排快照，drift 由现有 hash 公式保护

## 5. 非功能约束

### 5.1 Token 预算

各 Domain term + invariant desc token 估算（中英混合按 1.3 字符/token）：

| Domain | term 数 | desc chars | invariant chars | 小计 tokens |
|---|---:|---:|---:|---:|
| oxn-domain | 16 | 700 | 350 | ~800 |
| oxn-engine-domain | 9 | 430 | 1100 | ~1180 |
| oxn-cli-domain | 16 | 600 | 1400 | ~1540 |
| oxn-work-domain | 16 | 1100 | 1700 | ~2160 |
| oxn-asset-domain | 11 | 600 | 1200 | ~1470 |
| oxn-proof-domain | 13 | 800 | 1300 | ~1630 |
| oxn-insight-domain | 10 | 650 | 700 | ~1050 |

**理想态多视角注入**（Task 对齐 1 个主 Domain + Blueprint.use.domain 平均 3-5 个背景 Domain）：
- 主 Domain（含 invariants）：~1500-2200 tok
- 背景段（仅 term desc，不带 invariants）：~500-1200 tok × 3-5 = ~1500-6000 tok
- 总增量：~3000-8000 tok/Task

对比当前（单 Domain regex 单行截断 + invariants 全注入）：~800-1500 tok/Task

**净增量**：+2200-6500 tok/Task。对 32k context 模型占 7-20%，对 200k context 模型占 1.5-4%。

**缓解策略**（可选，留给 P3 实现）：
- 背景视角仅注入与主视角**同名 term**的 desc（不注入主视角未提的 term），把 token 增量压到 +1500-3000 tok
- 按 Blueprint.use 顺序截断（前 3 个背景 Domain 满注入，4+ 仅 term name 列表）

### 5.2 PlanLock 兼容性

P1 不动 `plan-hash.ts` 公式；P5/P6 加 workflow/stack 校验但**不引入新 hash 字段**。原因：

- `blueprintsHash` 已是 composite（含 Blueprint + Domain/Workflow/Stack 边界 hash）
- 加新 hash 字段会破坏旧 Work 的 `.work` 文件（schemaVersion: 1）

### 5.3 向后兼容

- P3 `## Allowed Language` 渲染格式变化：老 `oxn work context` human 输出格式不同 → 不影响 `--json` 路径（data 字段语义不变）
- P5 lock 期校验加新错误码：旧 Work lock 流程可能触发新错误，需 P7 deprecation warn 提前告知

### 5.4 ADR 一致性

| ADR | 当前状态 | 本 RFC 后状态 |
|---|---|---|
| ADR-0054 三边界框架 | 设计规范 | runtime 全落地 |
| ADR-0055 Blueprint 组合模板 | 仅 lock 期校验 | runtime 注入路径接通 |
| ADR-0059 Domain 引用模型 v2 | backlinks 已落 | 不受影响 |
| ADR-0060 D4 同名 multi-domain | 纸面规范 | runtime 多视角注入 |
| ADR-0060 D8 视角隔离 | 纸面规范 | `[Domain]` 标注实现 |
