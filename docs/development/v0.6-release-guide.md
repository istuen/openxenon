## 5. GitHub Release 流程

### 5.1 合并 PR

```bash
# PR-3 已开: feat/v0.6-iap-refactor → dev
# https://github.com/istuen/openxenon/pull/3
gh pr ready 3  # 标为非 draft (review 通过后)
# 在 GitHub UI merge
# 推荐: Squash and merge (清理中间 commits)
```

### 5.2 打 tag + 触发 release

```bash
# 在 main/dev 分支:
git checkout dev
git pull origin dev

# 创建 changelog 提交 (汇总 v0.6)
git log v0.5.0..HEAD --oneline  # 检查所有 commits

# 手动 bump version (root package.json + engine + cli)
# 选项 A: bun run version:aggregate  (自动聚合 .openxenon/ 资产到 changelog)
# 选项 B: 手动 edit

# 用 npm version 自动化
npm version 0.6.0 -m "v0.6.0: IAP 架构重构 + Monorepo 双包"
# 这会:
#   - 修改 package.json version
#   - 创建 commit "v0.6.0"
#   - 创建 tag v0.6.0

git push --follow-tags
```

### 5.3 GitHub Actions 自动发布

确保 `.github/workflows/release.yml` 存在 (如有)。如果不存在,需要创建:

```yaml
# .github/workflows/release.yml
name: Release
on:
  push:
    tags: ['v*']
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v1
      - run: bun install --frozen-lockfile
      - run: bun run build
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

### 5.4 手动 npm 发布（如不用 GitHub Actions）

```bash
# 1. 登录 npm
npm login

# 2. 验证 package.json fields
cat package.json | head -10
# 应含: "name": "@istuen/openxenon", "version": "0.6.0"
# 应含: "main", "bin", "files", "description"

# 3. dry-run 测试
npm publish --dry-run

# 4. 正式发布
npm publish
# → https://www.npmjs.com/package/@istuen/openxenon
```
