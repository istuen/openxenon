# 1. 系统介绍

## 什么是 OpenXenon

OpenXenon 是一个面向大语言模型（LLM）的工程化控制引擎。它的核心目标是解决 AI 编程工具中最棘手的问题：**如何在保持 AI 创造力的同时，确保工程输出的确定性和可追溯性**。

## 核心理念：综合集成研讨厅

OpenXenon 借鉴了钱老提出的"综合集成研讨厅"方法论：

- **定性经验（人类）**：工程师提供高层意图和约束
- **降维拆解（AI）**：大模型将自然语言转化为结构化的工程指令
- **定量判决（Core）**：Core 引擎通过物理验证确保执行正确性

```
工程师(定性) → AI(降维) → Core(定量)
```

## 核心价值

| 价值 | 说明 |
|------|------|
| **工程确权** | 所有 Blueprint 经过物理验证，确保工程契约不可篡改 |
| **逃逸检测** | AI 执行偏离原始 Blueprint 时，Core 自动熔断 |
| **人机协同** | AI 不是全知全能，工程师保留最终决策权 |
| **资产沉淀** | 通过 Draft/CANONICAL 生命周期管理工程标准 |

```
│         - Proof: 验证闭环                          │

```

## 与传统 AI 编程工具的区别

| 特性 | 传统 AI 编程工具 | OpenXenon |
|------|-----------------|-----------|
| 执行模式 | 放养式 | 围栏式 |
| 状态管理 | 无 | Blueprint 确权 |
| 错误处理 | AI 自行修正 | Core 熔断 + Sample 逃生 |
| 资产沉淀 | 无 | Draft → CANONICAL |
| 工程确定性 | 低 | 高 |

## 适用场景

- 需要 AI 辅助完成复杂工程任务的团队
- 对代码质量和执行确定性有较高要求的项目
- 需要积累和复用工程标准的企业
