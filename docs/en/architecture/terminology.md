# Terminology

This document defines core terminology used in OpenXenon.

## Roles and Responsibilities

| Term | Definition |
|------|------------|
| **Engineer** | Decision maker and verifier - defines intent, sets verification standards, reviews final results |
| **AI Assistant** | Dispatcher and executor - receives task goals, selects execution strategies, schedules Core CLI, performs code operations |
| **Core** | Judge and recorder - compiles assets, dispatches instructions, executes verification, records state |

## Core Concepts

| Term | Definition |
|------|------------|
| **Blueprint** | Task engineering drawing, defines execution topology (DAG) |
| **Stage** | Work node with four fields: target/action/spec/probes |
| **Probe** | Atomic check - physical observation + pure function evaluation |
| **Artifact** | Product built by AI, verified by Core |
| **Arsenal** | Asset library, stores all reusable engineering assets |

## Stage Fields

| Field | Visibility | Definition |
|-------|------------|------------|
| **target** | Visible to AI | Execution scope constraint |
| **action** | Visible to AI | Execution instruction to AI |
| **spec** | Hidden from AI | Engineer's structured intent constraint |
| **probes** | Hidden from AI | Probe set for verifying stage completion |

## Lifecycle

| Term | Definition |
|------|------------|
| **DRAFT** | Draft state, generated by AI through Forge, pending review |
| **CANONICAL** | Official state, passed engineer review, can be referenced by tasks |
| **Frozen** | Frozen snapshot, immutable execution plan after Blueprint compilation |
| **Trace** | Execution trace, Core's verdict record after executing Probes for each Stage |

## Task States

| State | Definition |
|-------|------------|
| **CREATED** | Task created, Blueprint saved |
| **IN_PROGRESS** | Task executing |
| **PASSED** | All Stages and Probes passed |
| **FAILED** | Some Probe failed |

## System Components

| Term | Definition |
|------|------------|
| **Kernel** | Pure function layer, zero side effects, only logical evaluation |
| **Infra** | I/O layer, only component touching filesystem and processes |
| **Forge** | Asset building process, transforms engineer experience into Schema-constrained assets |

## Information Hiding

| Principle | Description |
|-----------|-------------|
| **AI cannot perceive verification standards** | AI only sees target + action, cannot see spec + probes |
| **Core exclusively holds verification logic** | Verification standards managed by Core, AI cannot interfere |
| **Engineer doesn't介入实时审查** | Engineer only defines rules and verification results, doesn't participate in execution |
