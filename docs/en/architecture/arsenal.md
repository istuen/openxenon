# Arsenal

Arsenal is the repository storing all reusable engineering assets.

## Definition

Arsenal stores standardized assets defined by engineers and confirmed through review, including:

- Blueprint
- Stage
- Probe

## Directory Structure

```
.openxenon/
└── arsenals/
    ├── probes/
    │   ├── fs_exists/

    │       └── stage.yaml

    └── blueprints/
```

## DRAFT / CANONICAL Lifecycle

All Arsenal assets must go through a two-state lifecycle:

```
DRAFT ──[oxn arsenal promote]──▶ CANONICAL
(Draft)                           (Official)
```

| State | Meaning | Availability |
|-------|---------|--------------|
| DRAFT | Generated by AI via Forge, pending review | Cannot be referenced by tasks |
| CANONICAL | Passed engineer review, promoted | Can be referenced by tasks |

### Flow

```bash
# 1. AI generates Draft via Forge
oxn forge probe --save '<yaml>' --name my-check

# 2. Engineer reviews
oxn arsenal inspect probes/my-check

# 3. Promote to Canonical
oxn arsenal promote probes/my-check
```

## Built-in Assets

OpenXenon bundles built-in assets into binary at compile time, available everywhere:

```bash
# View built-in assets
oxn arsenal list
```

Built-in assets include:

- `fs_exists` - Check if file exists
- `fs_not_exists` - Check file doesn't exist
- `fs_match` - Check file content matches
- `shell_exec` - Execute command and check exit code

## Project-level vs Global-level

| Level | Path | Purpose |
|-------|------|---------|
| Project-level | `.openxenon/arsenals/` | Project-specific assets |
| Global-level | `~/.openxenon/arsenals/` | Cross-project shared assets (0.2) |

## Asset Value

- **Accumulating**: Good assets can precipitate as team standards
- **Reusable**: Assets can be reused across projects and tasks
- **Versionable**: Assets can be managed under Git
