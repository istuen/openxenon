## 2. v0.7+ apps/hall 目标

将 Hall 重新实现为独立 npm package，复用 v0.6 engine 的 L1-Infra/L0-Kernel 模块。

### 2.1 目标架构 (v0.7+)

```
openxenon (monorepo)
├── packages/
│   ├── engine/   (v0.6 已独立发布)
│   └── cli/      (v0.6 已独立)
├── apps/
│   └── hall/     (v0.7+ 目标)
│       ├── src/
│       │   ├── index.ts          # Hall 入口
│       │   ├── scanner/          # 文件系统扫描
│       │   │   ├── task-scanner.ts      # scanProjectTasks
│       │   │   ├── pool-scanner.ts      # scanIntentPools
│       │   │   └── arsenal-scanner.ts   # scanArsenalAssets
│       │   ├── render/          # HTML/CSS/JS 生成
│       │   │   ├── index-renderer.ts    # generateHallIndexHtml
│       │   │   └── task-detail.ts       # scanProjectTasksDetailed
│       │   └── server/          # HTTP server
│       │       └── hall-server.ts
│       └── package.json
```

### 2.2 依赖方向

```
apps/hall → packages/engine (read-only)
         → engine/infra/socket (IPC)
         → engine/infra/filesystem (FS read)
```

apps/hall **不依赖** packages/cli（独立 web 入口）。

### 2.3 与 v0.6 engine 的复用点

v0.6 engine 已提供 90% Hall 需要的 filesystem 抽象：

| Hall 需求 | v0.6 engine 等价模块 |
|---|---|
| 读 `.openxenon/` 布局 | `@openxenon/engine/infra/filesystem` |
| 扫 task state | `@openxenon/engine/Work/dual-state-io` (`scanProjectTasks` 可改为 read 引擎的 `TaskState`) |
| 读 task trace | `@openxenon/engine/Work/task-trace` (`readTaskTrace` 已实现) |
| Socket IPC (daemon 通信) | `@openxenon/engine/infra/socket.ts` |
| Probe catalog | `@openxenon/engine/kernel/verdicts/catalog` |
| 加载 builtin .oxn | 参考 `docs/architecture/v0.6-builtin-assets-scope.md` |

## 3. API 候选 (从原 `src/hall/index.ts` 提取 + 重构)

### 3.1 Scanner API

```typescript
// apps/hall/src/scanner/task-scanner.ts
export interface TaskSummary {
  taskId: string
  taskName: string
  status: 'CREATED' | 'RUNNING' | 'COMPLETED' | 'FAILED' | 'ABANDONED'
  updatedAt: number
}

export async function scanProjectTasks(projectRoot: string): Promise<TaskSummary[]>

export interface TaskDetails extends TaskSummary {
  parts: PartDetail[]
  probes: ProbeDetail[]
  trace: TraceEvent[]
}

export async function scanProjectTasksDetailed(projectRoot: string): Promise<TaskDetails[]>
```

**改进点** (vs v0.6 hall):
- 扫 `.openxenon/works/<w>/tasks/<t>/` 双层布局 (v0.6 TODO 已解决)
- 返回类型从 sync → async (与 engine Work 模块一致)
- 用 `TaskState` 类型代替 `unknown[]`

### 3.2 Render API

```typescript
// apps/hall/src/render/index-renderer.ts
export interface HallStats {
  totalTasks: number
  completedTasks: number
  failedTasks: number
  runningTasks: number
  pendingTasks: number
  draftAssets: number
  canonicalAssets: number
  arsenalProbes: number
  arsenalStages: number
  arsenalBlueprints: number
  recentTasks: TaskSummary[]
}

export async function getHallStats(projectRoot: string): Promise<HallStats>

export async function generateHallIndexHtml(projectRoot: string): Promise<string>

export async function renderHall(projectRoot: string): Promise<string>
```

**改进点**:
- HTML 模板用 v0.6 引入的 i18n (`@openxenon/engine/infra/i18n`)
- 错误状态 (probe FAIL) 用 v0.6 engine `TRUST_BASELINE` (interferenceFlags)
- 整合 `engine/kernel/verdicts/cross-proof-compute` 跨 task 的趋势分析

### 3.3 Server API

```typescript
// apps/hall/src/server/hall-server.ts
export interface HallServerOptions {
  port: number
  host?: string
  watch?: boolean  // v0.6 已有 ManifestWatcher
}

export async function startHallServer(options: HallServerOptions): Promise<void>
export async function stopHallServer(): Promise<void>
```

**改进点**:
- v0.7+ 走 HTTP server (替代 v0.6 的 `writeFileSync(index.html)`)
- 支持 SSE (Server-Sent Events) 推 task trace 更新
- 用 `engine/infra/socket.ts` 与 daemon 通信 (实时数据)

## 6. 边界与依赖

### 6.1 apps/hall **不应依赖**

- `packages/cli/` (CLI 入口是另一回事)
- `src/daemon/` (已迁 engine, 走 socket IPC)
- `apps/web/` (若有 v0.7+ 单独 web 入口)

### 6.2 apps/hall **可以依赖**

- `packages/engine/` (read-only) — TaskState, socket, filesystem, kernel types
- `engine/infra/i18n` (静态字符串)
- `engine/Work/dual-state-io` (只读 TaskState)

### 6.3 apps/hall **与 daemon 通信**

- 用 `engine/infra/socket.ts` 提供的 SocketMessage
- Daemon 主动推 `HallEvent` (已存在 `src/daemon/hall.ts` 130 行)
- apps/hall SSE bridge 转发到 web client

## 7. 风险与开放问题

### 7.1 风险

- **engine API 稳定性**: v0.7 前必须保证 engine 的 Work/Socket/FS API 不 breaking change
- **HTML 模板复杂度**: v0.6 hall 的 HTML/JS 模板含 ~400 行 inline JS，需要小心拆分
- **forges/ 兼容**: v0.6 hall 实现了 `warnOnForgesDeprecated`，需保留 (v0.7 Intent Pool 替代)

### 7.2 开放问题

- [ ] apps/hall 是否需要支持 file watcher (FSNotify / Bun.watch)?
- [ ] 实时 SSE vs 轮询 — 性能 vs 复杂度
- [ ] apps/hall 与 engine 共享 i18n 还是独立翻译?
- [ ] 跨 task 趋势分析应该放在 engine 还是 hall?
