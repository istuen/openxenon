## 三层分离

OpenXenon 采用严格的三层分离架构：

```
┌─────────────────────────────────────────────────────────────┐
│                    三层分离架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Kernel（纯函数层）                                          │
│  ├─ 零副作用                                                │
│  ├─ 只做逻辑判定                                            │
│  ├─ 可测试、可复现                                          │
│  └─ 不触碰文件系统/进程                                     │
│                                                              │
│  Infra（I/O 层）                                            │
│  ├─ 唯一触碰硬件的组件                                      │
│  ├─ 执行物理观测                                            │
│  ├─ 文件系统操作                                            │
│  └─ 进程执行                                                │
│                                                              │
│  Arsenal（资产层）                                          │
│  ├─ 内置资产                                                │
│  ├─ 编译进二进制                                            │
│  └─ 随处可用                                                │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 设计约束

| 约束 | 内容 | 原因 |
|------|------|------|
| AI 输出不可信 | 不直接采信 AI 声明，必须用观测验证 | AI 会幻觉，会撒谎 |
| 判定逻辑可复现 | Kernel 只做纯函数计算 | 保证判定结果可预测、可测试 |
| I/O 操作收敛 | Infra 是唯一触碰硬件的组件 | 防止侧路绕过验证 |

## 交互拓扑

```
工程师 ──▶ AI 助手 ──▶ Core CLI ──▶ AI 助手 ──▶ 工程师
  │          │           │          │           │
 下达      调度       返回指令     执行       验收
 目标      CLI       (隐藏标准)   Artifact   结果
```

**关键原则**：

- AI 助手无法感知验证标准（spec + probes）
- Core 独占验证逻辑
- 工程师不介入实时审查
