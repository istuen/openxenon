## Context

OpenXenon 是一个面向大语言模型的工程化控制引擎，通过"综合集成研讨厅"模式实现人机协同。当前缺乏系统性的文档，导致新用户难以理解系统架构和正确使用方式。

## Goals / Non-Goals

**Goals:**
- 编写完整的中文使用手册
- 覆盖所有 CLI 命令的正确用法
- 说明标准资产生成和管理的完整流程
- 提供故障排查指南

**Non-Goals:**
- 不编写开发者文档（API 内部实现细节）
- 不编写英文版手册
- 不实现自动文档生成工具

## Decisions

### Decision 1: 文档结构

**决定**: 采用分层结构

```
docs/manual/
├── 01-intro.md          # 系统介绍
├── 02-concepts.md       # 核心概念
├── 03-cli.md           # CLI 命令参考
├── 04-standards.md      # 标准资产生成流程
├── 05-troubleshooting.md # 故障排查
└── README.md            # 入口
```

**理由**:
- 按功能模块组织，便于查找
- 从概念到实践，循序渐进

### Decision 2: 文档风格

**决定**: 技术手册风格

- 使用代码块展示命令和配置示例
- 使用表格对比概念差异
- 使用 Callout（提示、警告）强调关键信息

**理由**:
- 便于工程师快速复制使用
- 关键信息一目了然

### Decision 3: 示例内容

**决定**: 基于 MVP 0.1 功能编写示例

- 基于 Blueprint YAML 模板
- 基于 Builtin Proofs（fs_exists, exec_exit_zero）
- 基于 Task 生命周期

**理由**:
- 与当前实现保持同步
- 便于工程师立即实践

## Risks / Trade-offs

[风险] 文档与代码实现不同步
→ **缓解**: 将文档纳入代码 review 流程

[风险] 文档过于冗长
→ **缓解**: 保持简洁，链接到相关资源而非重复内容
