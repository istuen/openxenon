## Context

当前文档措辞偏学术腔，体现在：

- README.md："核心假设 H1-H4"表格，附戏剧化结语"如果 H4 被证伪，项目价值为零"
- architecture.md："物理学公理"（公理一/二/三）、"物理学定稿"、"物理学框架"
- 自举定义表有"验证方式"列，写了具体验证脚本路径

这不是项目的真实声音。项目是工程实践，不是学术研究。

## Goals / Non-Goals

**Goals:**

- 让文档说人话：平实、直接、不装
- 把架构方案（三层架构）与架构原则（Kernel 纯函数）区分开
- 自举是里程碑，不是实验

**Non-Goals:**

- 不改变任何技术架构描述的准确性
- 不修改文档的逻辑结构（章节顺序不变）
- 不涉及任何代码变更

## Decisions

### 决策 1：删除"核心假设 H1-H4"，替换为"出发点"

**选择**：删除 H1-H4 表格，用一段话代替

**理由**：
- "假设"暗含"我们会做对比实验验证"，实际上没有这个计划
- 表格+指标+信心度，像开题报告，不是项目记录
- 替换为"出发点"：说明为什么做这个项目，不说"验证什么假设"

**替代考虑**：
- 保留 H1-H4 但去掉指标 → 还是学术腔，不够
- 改成"我们的信念" → 可以，但不如"出发点"直接

### 决策 2：删除"物理学公理"，改用"架构原则"

**选择**：删除"物理学公理"表格，改为简单的分层描述

**理由**：
- "公理"暗示不可违背，但三层架构是设计选择，可以改
- "Kernel 是兰姆达真空"是技术约束，不是物理定律
- 简单描述架构各层职责即可，不需要上升到"公理"

**替代考虑**：
- 保留"公理"但改名 → 改完还是换汤不换药
- 完全删除原则描述 → 失去架构指导，不行

### 决策 3：自举定义表删除"验证方式"列

**选择**：只保留"级别、定义、状态"三列

**理由**：
- 自举是工程里程碑，L2 通过就是通过，不需要量化指标
- 验证方式是工程细节，不适合放在文档里
- "状态"列已经足够表示进展

### 决策 4：统一架构词汇

**选择**：全局替换以下词汇

| 原文 | 改为 |
|------|------|
| 物理学架构 | 分层架构 |
| 三权分立 | 探针分为契约/能力/评判三层 |
| 物理学公理 | 架构原则 |
| 物理学定稿 | 已定稿 |
| 物理学框架 | 架构框架 |

**理由**：去掉"物理学"前缀，回归技术描述本质。

## Risks / Trade-offs

| 风险 | 描述 | 缓解 |
|------|------|------|
| 去掉学术腔后显得不够严肃 | 外部可能认为项目不专业 | 项目本质是工程实践，不是学术论文 |
| 架构描述变得模糊 | 去掉"公理"后架构约束不清晰 | 保留架构原则描述，只是去掉"不可违背"的措辞 |
