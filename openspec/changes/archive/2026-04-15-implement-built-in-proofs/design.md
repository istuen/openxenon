## Context

Xenonix 的 Proof 架构是整个工程体系的安全命脉。当前系统缺乏一个绝对可信的验证机制，存在 AI 通过篡改验证逻辑来伪造通过结果的风险。本设计旨在建立一个物理封印的、不可篡改的原子验证探针系统。

**当前状态**：
- 无内置探针系统
- 无自定义探针执行机制
- 无探针调度逻辑
- 无探针查看 CLI

**约束**：
- 技术栈：TypeScript + Bun
- 内置探针必须熔铸进二进制，不可在文件系统中寻址
- 自定义探针必须隔离执行，通过进程通信
- 验证结果必须是绝对布尔值（0 或 1），无灰度

## Goals / Non-Goals

**Goals:**
- 实现 L1-L4 四个物理层级的 12 个原子元格探针
- 建立内置探针的物理封印机制（编译时熔铸进二进制）
- 实现自定义探针的隔离执行机制
- 实现三段式降级查找调度逻辑
- 提供 `xn proof-list` CLI 指令查看所有可用探针

**Non-Goals:**
- 不实现 LLM 评判探针（禁止伪格）
- 不实现模糊评分机制（必须是布尔值）
- 不实现复杂业务逻辑校验（应拆解为原子探测）
- 不实现探针热加载机制（内置探针必须在编译时确定）

## Decisions

### D1: 内置探针存储形式——二进制熔铸

**决定**：内置探针硬编码在 Core 的 TypeScript 源码中，编译时利用 Bun 的打包能力直接熔铸进单一二进制文件。

**理由**：
- AI 无法看到源码、无法修改、无法在文件系统中寻址
- 构成绝对可信的验证基石
- 无文件 IO，零篡改可能

**备选方案**：
- 存储在加密的文件中：仍存在被解密和篡改的风险
- 运行时从远程加载：增加网络依赖，降低可靠性

### D2: 自定义探针执行机制——隔离子进程

**决定**：自定义探针通过 `Bun.spawn` 拉起隔离子进程执行，参数通过 stdin 喂入，只收割进程退出码。

**理由**：
- 自定义探针被视为不可信的外部契约
- 隔离执行保证 Core 不被污染
- 进程退出码（0 或 1）是绝对可信的结果

**备选方案**：
- 直接 `require` 并执行：可能导致恶意代码污染 Core 进程
- 使用 Worker 线程：隔离性不如进程级别强

### D3: 探针调度逻辑——三段式降级查找

**决定**：按优先级查找探针：内置 → 项目级自定义 → 全局自定义 → 熔断。

**优先级**：
1. **内置探针（内存字典）**：申请内置元格时，直接在二进制内存中调用底层引擎执行
2. **项目级自定义**：去当前项目的 `<project>/.xenonix/proofs/` 查找并隔离执行
3. **全局自定义**：去全局 `~/.xenonix/custom-proofs/` 查找并隔离执行
4. **终极熔断**：三层都没找到时，返回 `ProofNotFoundError`，判定 Step 为 FAILED

**理由**：
- 封死 AI 凭空捏造探针名字的漏洞
- 项目级优先保证特定业务需求的隔离
- 全局级提供通用扩展能力

### D4: 探针层级划分——L1-L4 四层物理现实

**决定**：将原子元格严格划分为 4 个物理层级。

**层级定义**：
- **L1 文件系统层**：`fs_exists`, `fs_not_exists`, `fs_content_match`, `fs_parseable`
- **L2 进程执行层**：`exec_exit_zero`, `exec_stdout_match`
- **L3 运行时状态层**：`db_query_bool`, `env_exists`
- **L4 网络拓扑层**：`http_status`

**理由**：
- 极度克制、绝对原子化、零语义判断
- 这十几个原子元格足以组合覆盖 99% 的工程场景
- 层级清晰，便于理解和维护

### D5: 探针列表查看——`xn proof-list` CLI 指令

**决定**：提供 `xn proof-list` CLI 指令，列出所有可用探针名称。

**输出格式**：
- 内置探针列表（标记为 `[built-in]`）
- 项目级自定义探针（标记为 `[project]`）
- 全局级自定义探针（标记为 `[global]`）

**理由**：
- 便于工程师了解可用探针
- 便于 AI 在 Playbook 中选择合适的探针
- 提升开发体验

## Risks / Trade-offs

**[R1] 内置探针扩展困难**
- 内置探针熔铸进二进制后，添加新探针需要重新编译和部署
- **缓解**：通过自定义探针机制提供扩展能力，内置探针仅包含最核心的原子元格

**[R2] 自定义探针性能开销**
- 隔离子进程执行比直接调用慢
- **缓解**：仅在必须时使用自定义探针，核心验证逻辑尽量使用内置探针

**[R3] 探针命名冲突**
- 项目级和全局级可能出现同名探针
- **缓解**：三段式降级查找保证项目级优先，明确文档说明命名规范

**[R4] 隔离执行环境配置**
- 自定义探针可能依赖特定环境（数据库连接、环境变量等）
- **缓解**：通过 stdin 传递参数，让探针自行处理环境依赖
